# BDD100K 车载视频行人跟踪：α-β 对比卡尔曼

[English](README.md)

![卡尔曼跟踪器在繁忙路口的效果](figures/tracking.gif)

*卡尔曼跟踪器在纽约一个繁忙路口的效果（BDD100K `00abd8a7-ecd6fc56`，每秒 5 帧），每种颜色是一个编号。*

这个项目在 BDD100K 行车记录仪视频里跟踪行人。检测器是我在 [P1](https://github.com/asiansumer/yolov8-bdd100k-pedestrian) 里训练的 YOLOv8m 行人检测器，跟踪器是我用 Python 从零写的 ByteTrack 式跟踪器。它接着我的 [MOT17 跟踪项目](https://github.com/asiansumer/mot17-tracking)，那个项目里我用了 α-β 和卡尔曼滤波，但其实没真正弄懂。

所以这次我从滤波器本身开始：先在一维模拟小车上一步步写出 α-β 和卡尔曼，再把卡尔曼扩展到 8 维的框，最后才接进跟踪器。每次实验跟踪器代码都一样，只换运动模型，这样比较才公平。每个模块都有 pytest 测试（共 23 个）。

## 怎么工作

```
BDD100K MOT 标注（每秒 5 帧）+ 每秒 30 帧的 .mov 视频
  -> 找标注和视频之间差几帧（用检测器 IoU 搜索）
  -> 抽出有标注的帧，写成 MOT17 格式的真值
  -> YOLOv8m 检测每一帧的行人（conf >= 0.1，低分框也留着）
  -> 每一帧：
       每条轨迹往前预测一帧（不预测 / α-β / 卡尔曼）
       第一轮：高分框（>= 0.4）和所有轨迹配对，用缓冲 IoU，贪心认领
       第二轮：低分框和还没配上的已确认轨迹配对
       没配上的轨迹：记丢失，丢 5 帧（1 秒）就删掉
       没被认领的高分框（>= 0.5）：开新轨迹
  -> TrackEval：HOTA、MOTA、IDF1
```

一共 7 关，每关建在上一关上：

| 关 | 内容 | 文件 |
|---|---|---|
| 1 | 一维小车模拟器：真实位置 + 带噪声的测量 | `sim1d.py` |
| 2 | 一维小车上的 α-β 滤波 | `alphabeta.py` |
| 3 | 一维卡尔曼：先测静止的墙，再加位置 + 速度 | `kalman.py` |
| 4 | 框的 8 维卡尔曼 `[cx, cy, a, h, vcx, vcy, va, vh]` | `kalman.py`、`box_utils.py` |
| 5 | BDD100K 数据：标注和视频对齐、抽帧、检测 | `bdd_io.py`、`scripts/prepare_bdd.py`、`scripts/detect_bdd.py` |
| 6 | ByteTrack 式跟踪器，三种运动模型 | `tracker.py`、`motion_models.py`、`scripts/run_track.py` |
| 7 | 评估和画图 | `scripts/evaluate.sh`、`scripts/make_figures.py` |

## 结果

BDD100K MOT 训练集里的 10 段视频：2030 个标注帧，1880 个行人。

| 运动模型 | HOTA | MOTA | IDF1 | 编号切换 | 发出编号 |
|---|---:|---:|---:|---:|---:|
| 不预测（框停在上次看到的位置） | 23.3 | 9.4 | 26.4 | 3170 | 1389 |
| α-β（α 0.9，β 0.5） | **30.5** | **18.1** | **37.1** | **1454** | 1689 |
| 卡尔曼，8 维框状态 | 28.5 | 16.5 | 35.3 | 1827 | 1519 |

![三种运动模型的 HOTA、MOTA、IDF1](figures/compare.png)

先猜下一帧人会走到哪，编号切换就少了 42%（卡尔曼）到 54%（α-β）。α-β 比卡尔曼还好，这让我挺意外，原因见发现 5。

绝对分数不高。为了分清是检测器的问题还是跟踪器的问题，我把真值框直接当成完美检测喂给跟踪器：

| 运动模型 | 用我的检测器 | 用完美检测 |
|---|---:|---:|
| 不预测 | 23.3 | 52.4 |
| α-β | 30.5 | 64.4 |
| 卡尔曼 | 28.5 | 56.3 |

（HOTA）两边都在拖后腿：检测器漏了大约一半的行人；就算框完全准，在这份数据里把前后帧的人对上也很难（发现 2）。

## 发现

### 发现 1：标注和视频差了几帧

![左：按时间取的帧；右：用检测器找到的偏移取的帧](figures/align.png)

Kaggle 版 BDD100K MOT 的视频是每秒 30 帧，标注是每秒 5 帧。按时间每 6 帧取一帧，框明显画歪了（左图）。所以每段视频我都把偏移从 -18 到 +6 个视频帧试一遍，在 3 个样本帧上跑检测器，挑检测框和标注框重叠最多的偏移。上图这段视频，偏移 0 时平均 IoU 约 0.28，偏移 -6 时是 0.55。

每段视频的偏移都不一样，所以必须逐段找：

| 视频 | 偏移（视频帧） | 对齐分数 |
|---|---:|---:|
| 00abd8a7-ecd6fc56 | -6 | 0.55 |
| 000d35d3-41990aa4 | -2 | 0.58 |
| 00699de6-58847872 | -7 | 0.54 |
| 002d290d-90f2bab2 | -7 | 0.35 |
| 007aeb45-c601742b | +2 | 0.46 |
| 01a01af7-76f6a476 | -4 | 0.52 |
| 0204aad7-8ad8ba92 | 0 | 0.60 |
| 02645e20-f0955341 | +2 | 0.40 |
| 000f157f-dab3a407 | -6 | 0.64 |
| 021cb34f-455d80a0 | -5 | 0.62 |

### 发现 2：每秒 5 帧、车又在动，前后两帧的框几乎不重叠

![同一个行人相邻两个标注帧的 IoU 分布](figures/frame_iou.png)

IoU 匹配默认同一个人下一帧的框会和这一帧的框重叠。这里经常不成立：所有标注行人里，相邻两帧的框有 40% IoU 低于 0.3，将近五分之一完全不重叠。两个标注帧之间隔 0.2 秒，车在开、在转弯，而且大部分行人很小（框高中位数 65 像素）。所以就算检测完美，HOTA 也只有 52 到 64。

### 发现 3：算 IoU 前把框撑大有用

既然很多框不重叠，我在算 IoU 之前把两个框都往四周各撑大 0.6 倍宽和高（“缓冲 IoU”，来自 C-BIoU 论文）。离得近但没碰上的框也能配上。

| HOTA | 不撑大 | 撑大 0.6 |
|---|---:|---:|
| 不预测 | 21.8 | 23.3 |
| α-β | 29.8 | 30.5 |
| 卡尔曼 | 26.8 | 28.5 |

第二轮低分框还是用普通 IoU，而且门槛更严（0.5）。分数在 0.1 到 0.4 之间的框，大约四分之三对不上任何标注行人。所以低分框只有正好落在一条已确认轨迹的预测位置上时才被相信，单独出现时永远不开新轨迹。

### 发现 4：ByteTrack 的卡尔曼噪声是给每秒 30 帧定的

ByteTrack 按框高设卡尔曼噪声：每帧位置 std 为 h/20，速度 std 为 h/160。这些数假设每秒 30 帧。每秒 5 帧时，人在两帧之间走的距离大约是 6 倍，滤波器对自己的速度太自信，学真实速度学得太慢。我改了两处：

- 过程噪声 Q 的标准差乘 4（方差乘 16）
- 新轨迹一开始的速度不确定度设为每帧 0.5 个框高，而不是 10/160

| 卡尔曼设定 | HOTA | 编号切换 |
|---|---:|---:|
| ByteTrack 原设定 | 25.3 | 2264 |
| 按 5 帧/秒重调 | **28.5** | **1827** |

这和第 3 关是同一个道理：P 大就是“我还不信自己的预测”，所以增益 K 大，滤波器会很快跟上测量。

### 发现 5：轨迹很短，所以“快点学会速度”最重要

一个行人平均只出现 12 个标注帧（中位数 8）。需要很多帧才学会速度的滤波器，根本等不到那时候。所以 β 大的 α-β 在这里赢了：

| α-β 设定 | HOTA |
|---|---:|
| α 0.75，β 0.1 | 26.1 |
| α 0.9，β 0.1 | 27.5 |
| α 0.9，β 0.5 | **30.5** |

β = 0.5 时，每次残差有一半进了速度，一两帧就能学到速度。卡尔曼在初始 P 很大时也能做到，但在我的调参里还是差了约 2 分 HOTA。

这个取舍我在第 2、3 关的一维小车上就见过。那时小车一开始速度猜错了：慢的 α-β（α 0.1，β 0.01）一直追不上，位置平均误差 2.68 米；直接用测量是 0.313 米；卡尔曼是 0.178 米，因为它的增益一开始接近 1，越来越有把握后降到 0.23 左右。固定的 α-β 只能在“快”和“稳”之间选一个，卡尔曼会随时间自己调增益。在这份数据里，轨迹还没等到卡尔曼“稳”的优势发挥出来就结束了，所以“快”赢了。

## 运行

Python 3.10，需要 numpy、pandas、pyarrow、opencv-python、ultralytics、matplotlib、pytest。TrackEval 放在单独的环境里（numpy < 1.24），克隆在仓库旁边的 `../TrackEval`。检测器权重放在 `../yolov8-bdd100k-pedestrian/runs/yolov8m_bdd100k_pedestrian.pt`（P1 的 Releases 里有）。

**数据。** 从 Kaggle 数据集 `robikscube/driving-video-with-object-tracking` 下载：

- `mot_labels.parquet` -> `data/bdd_mot/mot_labels.parquet`
- `scripts/prepare_bdd.py` 里 `VIDEOS` 列出的 10 段视频 -> `data/bdd_mot/videos/<视频名>.mov`

**运行。** 在仓库根目录：

```bash
python -m pytest -q                # 23 个测试
python -m scripts.prepare_bdd      # 找偏移、抽帧、写真值（约 5 分钟）
python -m scripts.detect_bdd       # 检测 -> dets/（默认 mps，其他电脑传 cpu）
python -m scripts.run_track        # 三种运动模型 -> results/
bash scripts/evaluate.sh           # TrackEval，在 numpy < 1.24 的环境里跑
python -m scripts.make_figures     # figures/（也可以只画一张：compare frame_iou align gif）
```

第 1～3 关的一维实验：`python -m scripts.plot_noise`、`python -m scripts.run_alphabeta`、`python -m scripts.run_kalman_static`、`python -m scripts.run_kalman_car`。

## 项目结构

```
sim1d.py          一维小车：真实位置和带噪声的测量
alphabeta.py      α-β 的一步
kalman.py         一维和矩阵卡尔曼、框的 F/H、框的噪声 Q/R、拆开的预测/更新
box_utils.py      框的转换（x1 y1 x2 y2 <-> cx cy a h）和 IoU
metrics.py        一维实验用的平均绝对误差
bdd_io.py         读 BDD 标注，写 MOT17 格式真值和 seqinfo，读检测结果
motion_models.py  不预测 / α-β / 卡尔曼，都有同样 4 个函数
tracker.py        缓冲 IoU、贪心匹配、ByteTrack 式跟踪器
scripts/          每关一个脚本，加上 evaluate.sh 和 make_figures.py
tests/            pytest 测试
figures/          README 里的图
```

## 局限和下一步

- **在测试集上调参。** 跟踪器参数是在评估用的同一批 10 段视频上选的，分数偏乐观。更严谨的做法是一部分视频调参、另一部分报告结果。
- **检测器是最大的瓶颈。** 在跟踪用的阈值下，它只找到大约一半的标注行人，而且大部分行人很小。
- **没有外观特征。** 每秒 5 帧、相机在动，只靠位置常常分不清谁是谁。常用的办法是加 ReID 特征（DeepSORT、BoT-SORT 那样）。
- **没有相机运动补偿。** 车转弯时所有框会往同一个方向移。从图像里估计这个移动、在预测前减掉（BoT-SORT 的做法），两种滤波都应该会更好。
- **在图像里假设匀速。** 车往前开时，离车近的行人在图像里会越走越快。在地面坐标里建运动模型会更真实。
- **评估时忽略“人群框”**，和 BDD100K 官方规则一样。
